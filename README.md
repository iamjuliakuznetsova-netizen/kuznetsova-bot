# Бот KUZNETSOVA CREATES — один бот, много сценариев

Общая инфраструктура под все бесплатные лид-магниты Юлии. Человек комментирует
кодовое слово под постом в Instagram → получает в директ два сообщения через
ChatPlace (это отдельная механика, к этому боту не относится) → по кнопке
попадает в этого бота по персональной ссылке (диплинку). Дальше бот сам:
показывает приветствие, при необходимости просит подписаться на канал,
выдаёт материал и приглашает в Клод-клуб.

Первый готовый сценарий — **upakovka** (гайд «10 промтов для упаковки
аккаунта»). Новые сценарии добавляются файлом в папку `scenarios/`, без
переписывания бота.

## Шаг 1. Создать бота в BotFather

1. В Telegram найдите **@BotFather** и напишите ему `/newbot`.
2. Придумайте имя бота (то, что видят люди) и username — он обязательно
   должен заканчиваться на `bot`, например `kuznetsova_upakovka_bot`.
3. BotFather пришлёт **токен** — длинную строку вида `123456789:AAExampleToken`.
   Это ключ доступа к боту, никому его не показывайте и не публикуйте.

## Шаг 2. Добавить бота администратором канала

Бот проверяет подписку людей на канал KUZNETSOVA CREATES
(`@semero4ka_videomaker`), а без прав администратора Telegram не разрешит
боту такую проверку.

1. Откройте канал `@semero4ka_videomaker` → «Управление каналом» →
   «Администраторы» → «Добавить администратора».
2. Найдите вашего бота по username и добавьте. Отдельные права можно не
   выдавать — достаточно того, что он состоит в администраторах.

## Шаг 3. Настроить переменные окружения

1. Скопируйте файл `.env.example` в `.env`:

```bash
cp .env.example .env
```

2. Откройте `.env` в любом текстовом редакторе и вставьте токен из шага 1:

```
BOT_TOKEN=вставьте-сюда-токен-от-BotFather
```

3. Остальные значения (`MAIN_CHANNEL`, `KLOD_KLUB_URL`) уже заполнены
   правильно, трогать не нужно.

4. **`UPAKOVKA_GUIDE_URL`** сейчас стоит как заглушка
   (`https://example.tilda.ws/upakovka`). Когда будет готова реальная
   страница с гайдом на Тильде — замените значение на настоящую ссылку.
   Без этого бот будет присылать людям нерабочую ссылку-заглушку.

## Шаг 4. Запустить бота

Локально для проверки (нужен Python 3.11 или новее):

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python main.py
```

Если в терминале появилось «Бот запущен, ждём сообщения...» — всё работает.
Проверьте на телефоне: перейдите по ссылке `https://t.me/имя_вашего_бота?start=upakovka`
и пройдите весь путь сами.

Чтобы бот работал круглосуточно, а не только пока открыт ваш ноутбук, его
нужно перенести на хостинг — см. шаг 5.

## Шаг 5. Деплой (текущее состояние: развёрнуто на Timeweb Cloud)

Бот работает на облачном сервере Timeweb Cloud (Москва), IP `72.56.236.3`,
под управлением `systemd` — при падении или перезагрузке сервера бот
поднимается сам, вход по SSH-ключу (без пароля).

Где что на сервере:
- Код: `/opt/kuznetsova-bot/app` (клонирован из [GitHub-репозитория](https://github.com/iamjuliakuznetsova-netizen/kuznetsova-bot))
- Виртуальное окружение: `/opt/kuznetsova-bot/app/venv`
- `.env` с реальными токеном и ссылками: `/opt/kuznetsova-bot/app/.env` (только на сервере, в git не попадает)
- База данных: `/opt/kuznetsova-bot/app/bot.db`
- Служба автозапуска: `/etc/systemd/system/kuznetsova-bot.service`, запущена от отдельного системного пользователя `bot`

Полезные команды (через SSH):
```bash
# посмотреть статус
systemctl status kuznetsova-bot.service

# посмотреть логи (последние 50 строк)
journalctl -u kuznetsova-bot.service -n 50 --no-pager

# перезапустить (например, после обновления кода)
systemctl restart kuznetsova-bot.service

# обновить код до последней версии из GitHub и перезапустить
cd /opt/kuznetsova-bot/app && sudo -u bot git pull && sudo -u bot venv/bin/pip install -q -r requirements.txt && systemctl restart kuznetsova-bot.service
```

**BotHost больше не используется** — бот оттуда остановлен 2026-08-02, чтобы
не конфликтовать за один токен с сервером. Подписку/бота там можно
отключить/удалить.

## Как добавить новый лид-магнит (сценарий) в будущем

Это можно сделать без программиста.

1. Откройте папку `scenarios/`, скопируйте файл `upakovka.py`, переименуйте
   копию (например, `capcut.py`).
2. В новом файле замените:
   - `"key"` — короткое английское слово-идентификатор (например `capcut`),
     оно же будет параметром ссылки: `?start=capcut`
   - `"welcome_text"` — текст приветствия для этого лид-магнита
   - `"require_subscription"` — `True`, если нужна проверка подписки на
     канал, `False`, если не нужна
   - `"delivery_text"` — текст выдачи, `{guide_url}` — место, куда
     подставится ссылка на материал
   - `"guide_url_env"` — название новой переменной окружения для ссылки,
     например `CAPCUT_GUIDE_URL`
   - `"offer_klod_klub"` — `True`, если после выдачи показывать приглашение
     в Клод-клуб (текст приглашения общий для всех сценариев, менять не
     нужно)
3. Откройте `scenarios/__init__.py`, добавьте новый сценарий в словарь:

```python
from . import upakovka
from . import capcut  # новая строка

REGISTRY = {
    upakovka.SCENARIO["key"]: upakovka.SCENARIO,
    capcut.SCENARIO["key"]: capcut.SCENARIO,  # новая строка
}
```

4. В `.env` добавьте новую переменную со ссылкой, например:

```
CAPCUT_GUIDE_URL=https://...
```

5. Перезапустите бота (остановить `python main.py` и запустить заново, или
   перезапустить сервис на хостинге).
6. Готовая ссылка для рассылки: `https://t.me/имя_вашего_бота?start=capcut`

Ни `engine.py`, ни `db.py`, ни файлы в `handlers/` трогать не нужно —
вся общая логика (приветствие → подписка → выдача → Клод-клуб) уже есть и
работает одинаково для любого сценария.

## Структура проекта

```
main.py                  — точка входа, запуск бота (long polling)
config.py                — чтение настроек из .env
db.py                    — SQLite: пользователи и прогресс по сценариям
engine.py                — общая логика: приветствие → подписка → выдача → Клод-клуб
scenarios/
  __init__.py             — реестр сценариев (REGISTRY)
  upakovka.py              — конфиг первого лид-магнита
handlers/
  start.py                 — /start <параметр> и кнопка «Старт»
  subscription.py          — кнопка «Готово» (перепроверка подписки)
requirements.txt
.env.example
```

## База данных

Хранится в файле `bot.db` (создаётся автоматически при первом запуске).

- **`users`** — один человек = одна строка, независимо от того, сколько
  лид-магнитов он прошёл. Здесь же хранится, подтверждена ли подписка на
  канал — один раз подтверждённая подписка работает для всех сценариев.
- **`scenario_progress`** — одна строка на пару «человек + сценарий»: когда
  зашёл, когда получил материал, когда получил приглашение в Клод-клуб.
  Так один и тот же человек может пройти несколько разных лид-магнитов, и
  они не будут мешать друг другу.
